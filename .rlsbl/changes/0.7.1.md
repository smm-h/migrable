## 0.7.1

Retract correction: the 0.7.0 interval missed pseudo-versions.

<details>
<summary>Context</summary>

migrable is retired. 0.7.0 retracted `[v0.0.0, v0.7.0]`, but a closed interval
ending at a release excludes the pseudo-versions the module proxy synthesises
for untagged commits, so `go install github.com/smm-h/migrable@latest` kept
resolving to a pseudo-version built from the branch tip and installing the
retired tool. The interval is now `[v0.0.0-0, v0.7.1]`: `v0.0.0-0` is the
lowest possible pre-release, so every pseudo-version below the upper bound is
inside it, and the upper bound covers this release itself.

This release also corrects the 0.7.0 notes, which claimed the PyPI releases
were yanked. They are not; the yank is still pending and must be done by hand.

Only the go target publishes. Publishing a fresh npm or PyPI artifact would
create a version outside the existing npm deprecation and ahead of the pending
PyPI yank, undoing the retirement this release is meant to complete.

</details>

### Fixes

- **`go install ...@latest` no longer installs the retired tool.** The 0.7.0 retract interval `[v0.0.0, v0.7.0]` excluded pseudo-versions, so `@latest` still resolved to a pseudo-version built from the branch tip. The interval is now `[v0.0.0-0, v0.7.1]`, which starts below every possible pseudo-version and includes this release itself.
- **Corrected a false claim in the 0.7.0 release notes.** They stated the PyPI releases were yanked; they are not. The notes now say the PyPI yank is pending and must be done manually.
